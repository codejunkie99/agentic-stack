# Agentic Stack Desktop Preview 0.19.1 — Graph-first work

**Candidate: `v0.19.1-desktop-preview.7`.** Build 7 was rebuilt from `6ac5911`
with a compact topic/source picker shared by Work and Browse. Latest tests,
isolated and installed native checks, independent package verification and
the matching Sparkle signature passed. The exact installed app passed strict
signature verification; original knowledge hashes stayed unchanged. The chosen
route is Sparkle 2.9.6 EdDSA-authenticated preview updates with ad-hoc signatures.
Preview 7 metadata is prepared locally; the live feed remains build 6 and the
release is unpublished. Developer ID/notarization are a separate optional route.

## What changed

- Work opens a 3D knowledge graph with the composer below it. Switch to the
  conversation without losing the work; inspect context beside the graph or in
  a compact-window sheet. The existing 2D and full-page graph modes remain.
- Work and Browse share one compact Spotlight-style topic/source picker,
  replacing the graph menus and topic-chip wall. Search the same field, switch
  All/Topics/Sources, apply with arrows/Enter or a click, and clear active chips.
  Topic rows count notes; source rows count files. Search and pagination reach
  all 112 observed topics, beyond the former 80-topic cap. Topic-label search
  uses case-insensitive literal multiword matching.
- The sidebar organizes Work, Memory and Connections, with visible Skills,
  Insights and recent work. Memory contains Browse, Lessons, References and
  Exports. Terminal, loops, handover, trust, references and hosted workflows
  remain available.
- Lessons chooses a populated category and separates accepted/review items from
  imported lesson stores. References browses all imported source files through
  pagination and full-text search alongside project references; the reader
  shows complete stored notes, paths, lines and review states.
- Command-K opens Spotlight with grouped Work, Memory, Conversations, Skills
  and Actions. Conversation search defaults to the project, with an explicit
  All conversations option. External conversation and skill results open
  previews; attaching a conversation does not send a message.
- Typing `@` or using the composer's conversation attachment control opens a
  separate conversation-only Spotlight. It defaults to all tools and projects,
  shows tool/project/model metadata and excerpts, supports filters and loading
  more results, and attaches removable chips without submitting the draft.
- The composer's compact model and effort popover applies model selection
  immediately and saves effort adjustments without an Apply/Cancel modal.
  Failed saves restore the last confirmed selection and show an error.
- Persistent work connects an objective, conversations, runs and a checkpoint.
  Continue with Codex or Claude Code opens a fresh runner session with that
  checkpoint; existing conversations retain their own CLI session.
- Context retrieval offers Off, local search or an optional retrieval agent.
  Budgeted packs show sourced excerpts, digests, estimated tokens, timing and
  cache state. Pin or exclude evidence and preview the next message's context.
  Codex retrieval defaults to GPT-5.6 Luna; Claude Code defaults to Haiku.
  Unavailable agent retrieval falls back to local search with a warning. This
  is bounded context selection, not literal infinite context. Candidate
  discovery uses keyword overlap; synonym-only requests can miss relevant
  sources before the optional ranker runs.
- Memory review records Reference, Accepted, Superseded and Retracted states
  with reasons and history. Superseded and retracted evidence stays inspectable
  and is excluded from automatic retrieval. Acceptance grants no execution
  permission.
- Exports previews sanitized local metrics, training and evaluation artifacts
  from eligible reviewed runs or existing approved records. Approval generates
  the displayed files; changed inputs require another preview. This exports
  records and does not train or fine-tune a model.
- Exports also discovers supported existing project export files, labels them
  separately from desktop-generated artifacts, and reads them with workspace,
  symlink and size safeguards. Empty projects show actual zero counts and
  generation options. Existing approved-file input is selected when available;
  browsing creates no files, approvals or training material.

## Sparkle preview update and installer verification

Actual native app copies completed Check for Updates → download → Install and
Relaunch from build 6 to 7; About showed `0.19.1 (7)`. A unique QA bundle ID,
a launcher forcing isolated data on every launch, a local feed and a separately
EdDSA-signed QA archive kept production bytes and original data unchanged.
The production preview 7 ZIP's signature is independently verified.

The actual installer script passed with only `curl` replaced by a local-file
copy shim. Checksum verification, read-only DMG mounting, bundle signature,
installation and backup operations were real; a tampered archive was rejected
before replacement. The test preserved the previous disposable installation
and did not touch the user's app or launch the installed copy.

These checks establish updater and local installer behavior, not production
HTTPS delivery or first-install Gatekeeper acceptance. macOS may still block
an unnotarized preview's first launch. Developer ID/notarization remain separate
from the chosen Sparkle preview route; publication has not occurred.

## Release tooling

These changes leave installed source `6ac5911` and its archives unchanged.
The signing helper plans 19 actual bundle targets inside out: 13 Python, five
Sparkle and the app. Valid Developer ID signing uses runtime/timestamp flags,
preserves Downloader entitlements and rejects invalid identities or escaping
links before signing. Ad-hoc behavior remains unchanged.

Self-checks, mocked Developer ID commands and disposable ad-hoc signing/strict
verification with SSL/SQLite imports passed. Real Developer ID signing and
notarization remain unavailable; broad native QA was not rerun. Temporary
Sparkle resolution passed on a copied package. The [release procedure](../releasing.md)
starts with the chosen preview route and exact Sparkle enclosure authentication.
Its optional notarized route retains the final staple/archive/sign sequence
and separately signed/notarized DMG.
