# v0.20 spec addendum — consolidation-driven deltas

Status: proposal against `v0.20-agentic-turn.md` (draft).
Origin: consolidation post-mortem, 2026-09-03 (see the private agent-brain
repository, `docs/DECISIONS.md` and `ralph/STATE.md`).

Four changes to the spec, each with the section it amends.

## A1. Subgoal acceptance criteria (amends §2.1 Plans layer)

The plan object's subgoals carry owners, dependencies, and skill hints — but
no definition of done. Verification lives one layer down (loop contract
`verification.command`), and nothing connects the two. The chain from intent
to executable specification breaks at exactly the translation step.

Change: add to the subgoal object —

```json
"acceptance": [
  {"kind": "shell", "spec": "pytest tests/test_upgrade.py -q", "status": "unmet|met"}
]
```

`plan.py decompose` MUST emit at least one acceptance stub per subgoal;
`plan.py next` skips subgoals whose acceptance list is empty (with a warning).
A subgoal is `done` only when every acceptance item is `met` or explicitly
waived by a human.

## A2. Requirement-to-check traceability (new check, sibling of §2.3)

Evals turn *lessons* into contracts; nothing does the same for new work.
Add a `trace.py check` verb: every plan subgoal has ≥1 acceptance item, and
every acceptance item traces to exactly one subgoal. This is
`find-untested-sources` discipline applied one level up.

## A3. Skill-level evals (amends §2.3 Eval runner)

Lessons get regression evals and auto-quarantine; skills get only the act
skill-critic after three failures. Skills are code-like and deserve the same
contract discipline. Change: `cases/` accepts `skill:<name>.yaml` fixtures
alongside `cases/<lesson_id>.yaml`; the same judges apply; a failing skill
eval sets the skill's manifest `recall_status: quarantined`, which
`_index.md` rendering excludes — one filter chain for both lessons and skills.

## A4. Unified human-gate queue (amends §2.8, touches §2.2/§2.7)

Human approvals currently fragment across five inboxes: `act/proposals/`,
trial scoreboards, the lesson review queue, PRs, and plans. The brain already
has gate discipline (review queue thresholds: >10 pending or oldest >7 days
blocks new work). Extend that one queue to all gates: a single
`~/.agent/gates/QUEUE.md` rendering every pending human decision from every
subsystem, one SLA, one session-start check. Without it the runtime's
throughput ceiling is five unwatched inboxes.

## A5. §2.6 federation vs agent-brain reconciliation (amends §2.6)

`~/.agentic-stack/global/` as specced risks becoming a fifth source of truth
(the consolidation exists because four was already too many). One paragraph
resolves it: the private `agent-brain` repository is the content source of
truth; `~/.agentic-stack/global/` is a machine-local read cache plus memory
backup; `federate.py promote` writes back to agent-brain by pull request,
never directly to global. Content identity (content-hash × project_id) is
only computable after consolidation — which landed 2026-09-03 — so the
promotion rule is now well-defined.

## Sequencing note

The consolidation precondition is met: single content source
(agent-brain v1.0.0+), single memory store (~/.agent + agent-memory weekly
backup), one distribution pipeline with a drift detector. Federation,
trials, and act can build on identity semantics that now actually hold.
